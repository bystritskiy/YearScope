# Источники: как устроено и почему так

Технические заметки по каждому источнику. Короткий обзор в [README](../README.md).

| Активность | Откуда | Детализация | Как берётся |
|---|---|---|---|
| 🎮 Игры | gowithme.club | по дням | `GET /api/player?name=…&period=year&include=byDayGames` → `byDay`, `byDayGames`, `topGames` |
| 🎬 Кино | Letterboxd | по дням | RSS + хронометраж из TMDB по `tmdb:movieId` |
| 📚 Книги | KoShelf | по дням | `GET /api/reading/calendar?month=…` за месяцы с данными |
| 📺 Сериалы | myshows | по дням | выгрузка профиля из `data/imports/*.xlsx` + `profile.Feed` |
| 🏃 Тренировки | intervals.icu | по дням | `GET /api/v1/athlete/{id}/activities?oldest=…&newest=…` |

## Кино

**Letterboxd** закрыт Cloudflare, публичного API нет, а RSS отдаёт лишь ~50 последних записей. Поэтому просмотры **накапливаются**: каждая синхронизация дописывает новое в `entries` по `guid`, а выпавшее из ленты остаётся в базе. Дневной ряд пересобирается из накопленного, а не из ленты.

**Хронометраж фильмов** кэшируется в `film_runtime` навсегда: TMDB дёргается только за новыми id. Без `TMDB_API_KEY` время считается по средней длительности (115 мин) и помечается в интерфейсе как оценка.

## Сериалы

**myshows** не отдаёт историю публично: `profile.Feed` возвращает 25 последних отметок и игнорирует пагинацию, а `profile.Episodes` требует авторизации. Поэтому история берётся из **выгрузки профиля**, а лента добирает отмеченное после неё. Обе половины называют сериал оригинальным названием и дают номер серии, так что ключ `сериал|s01e04` совпадает, и эпизод из двух источников схлопывается в одну запись. Если между датой выгрузки и окном ленты образуется провал, сервис пишет об этом на экране и просит обновить выгрузку.

Выгрузка кладётся в `data/imports/` (берётся самый свежий `.xlsx`). Папки нет в репозитории: это личные данные. Она примонтирована томом, так что переживает пересоздание контейнера.

## Тренировки

**Берутся из intervals.icu, а не из Garmin.** С часов они туда прилетают сами, а доступ несравнимо проще: HTTP Basic, где в качестве логина идёт литерал `API_KEY`, а в качестве пароля персональный ключ из Settings → Developer Settings. Ни OAuth, ни пароля от аккаунта, ключ отзывается в один клик. Весь год приезжает одним запросом.

Время считается по `moving_time`: он честнее для «сколько занимался». Но у силовых и йоги он часто нулевой, поэтому там берётся `elapsed_time`.

## Игры

**gowithme** пересчитывает прошлое задним числом, поэтому дневной ряд за год заменяется целиком, а не дописывается.

Игры приходят из opt-in `byDayGames` (агрегат день × игра, сумма сходится с `byDay`). Сырой лог сессий при необходимости берётся из `GET /api/player/sessions`.

## Книги

**KoShelf нужен по сети**, укажи его адрес в `KOSHELF_BASE_URL`. Из Docker Desktop на маке локальная сеть не видна вообще (любой порт LAN даёт refused), поэтому там книги синхронизируются только при запуске через `npm start`, без контейнера.

**Часовой пояс** контейнера должен совпадать с KoShelf, иначе чтение разложится по соседним дням.

## Модель данных

Источники отдают разную детализацию, и подгонять их под общий знаменатель значит врать. Поэтому:

- `daily` / `monthly`: временные ряды; на чтении берётся тот, что доступен, а гранулярность видна в API;
- `entries`: то, у чего есть настоящая дата (просмотр фильма, серия);
- `highlights`: топы вроде «во что больше играл»: у таких элементов одной даты нет, и в дневной ряд они не попадают;
- `sync_state`: статус источника, включая `covers_from`: с какой даты у него вообще есть данные.

`covers_from` это не техническая деталь: если источник знает только полгода, это написано на экране рядом с итогом, а не подразумевается.

## Настройка

Всё через `.env`. Обязательных полей нет: незаполненный источник просто выключается, остальные работают.

| Переменная | Зачем |
|---|---|
| `GOWITHME_PLAYER`, `LETTERBOXD_USER`, `MYSHOWS_LOGIN` | ники в этих сервисах |
| `KOSHELF_BASE_URL` | адрес KoShelf в сети |
| `INTERVALS_API_KEY`, `INTERVALS_ATHLETE_ID` | тренировки из intervals.icu |
| `TMDB_API_KEY` | точный хронометраж фильмов (без него оценка по средней длительности) |

История сериалов берётся из выгрузки профиля myshows: положи `.xlsx` в `data/imports/`.

Остальное (порт, год, частота синхронизации, часовой пояс) есть в [`.env.example`](../.env.example) со значениями по умолчанию.

## Экспорт

Кнопка **Экспорт** отдаёт год целиком: JSON со сводкой, журналом и топами, или плоский CSV для Excel.

## API

| Метод | Назначение |
|---|---|
| `GET /api/summary?year=2026` | всё, что рисует сводку |
| `GET /api/journal?year=2026&source=myshows` | лента активностей по дням, сверху свежее |
| `GET /api/source?id=myshows&year=2026` | один источник: полный рейтинг и его лента |
| `GET /api/export?year=2026&format=json` | скачать всё за год (сводка, журнал, топы) |
| `GET /api/export?year=2026&format=csv` | скачать плоский журнал для Excel |
| `POST /api/sync` | синхронизация вручную (идемпотентна: повторный вызов присоединяется к текущей) |
| `GET /api/health` | статус и признак идущей синхронизации |

Фоновая синхронизация идёт раз в `SYNC_INTERVAL_MINUTES` (по умолчанию 1440, то есть сутки) и один раз на старте. Отсчёт идёт от запуска сервиса, а не от полуночи: перезапустил в 15:00, значит следующая синхронизация в 15:00 следующего дня.

## Демо-режим

`npm run demo` заполняет базу вымышленным годом и не ходит в сеть вообще. Нужен для скриншотов и для того, чтобы проект можно было посмотреть, не заводя аккаунты в пяти сервисах.

Генератор [`src/demo.ts`](../src/demo.ts) детерминированный: один и тот же год даёт одну и ту же картинку, иначе каждый пересъём скриншотов менял бы все числа в README. Демо-база лежит отдельно, в `data/demo`, и настоящую не затирает. Кнопка «Обновить» в демо перегенерирует год вместо опроса источников.

Книги в демо «начинаются» с 10 июня: так на экране видно и оговорку о неполном покрытии: в продукте она на видном месте.
